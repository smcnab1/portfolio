# Portfolio project guidance

- This repository contains Sam's professional portfolio at sammcnab.co.uk. Use the current README, source, package.json, lockfile and repository policies as the implementation baseline.
- Inspect the working tree and preserve unrelated edits. Keep changes focused on the requested outcome; do not redesign or upgrade dependencies merely to match an old chat.
- Use the Node version and npm version declared by the repository. Follow existing scripts and conventions instead of switching package managers or introducing parallel configuration.
- Use UK English in prose. Verify Sam's current biography, roles, qualifications, project claims and links against supplied evidence before publishing them. Do not infer current employment from historical copy.
- Preserve accessibility, responsive behaviour, theme support and working navigation. Use current official framework documentation when a version-specific decision matters.
- Run proportionate checks from package.json for implementation changes. Relevant checks currently include lint, typecheck, test, format:check and build; reinspect scripts before use. Documentation-only changes need a focused content/diff review, not the entire application test suite.
- Keep secrets and private application or case material out of the public site, logs, fixtures and documentation.
- Keep durable architecture and usage guidance in the repository. Record changing release/deployment facts with evidence and a verification date; old chat reports are historical context.
- Report the concrete change, actual validation and remaining gaps concisely. Commit, push, deployment and external communication require the actual task's authorisation.
